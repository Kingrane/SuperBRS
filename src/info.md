### 1. Официальное резюме проекта (можно сразу вставлять в паспорт проекта и на 1-й слайд)

SuperBRS — единая цифровая витрина успеваемости и расписания с интеллектуальным ассистентом. Текущий сервис БРС ЮФУ морально устарел, неудобен с телефона и существует отдельно от расписания, поэтому мы разрабатываем единый современный веб-сервис, который объединит оценки и пары в удобном и быстром интерфейсе. Мы сделаем мгновенную загрузку за счет кэширования, чтобы всё открывалось даже при сбоях официального сайта, и встроим умного ИИ-ассистента, у которого можно будет прямо в чате спросить, в какой аудитории сейчас ведет пару нужный преподаватель или сколько баллов не хватает до зачета. Разрабатывать проект будем на связке React, Tailwind и C# (ASP.NET Core), ищем в команду первокурсников, которым интересно веб-программирование: научим веб технологиям и вместе сделаем мощный продукт, которым будут реально пользоваться студенты.

### 2. Разбор стека: C#, Tailwind, Redux и кэш

#### Получится ли бэкенд на C#?
**Да, и это даже жирный плюс перед жюри.** 
На мехмате и в IT-индустрии к ASP.NET Core (C#) относятся с большим уважением: это взрослый, строго типизированный, промышленный стек.
* **Как это будет работать:** Второкурсник создает проект `ASP.NET Core Web API`. Бэкенд делает HTTP-запросы (через `HttpClient`) к официальным серверам БРС и Расписания ЮФУ, очищает полученные данные, упаковывает их в понятные DTO-модели и отдает вашему React-приложению. 
* Также на C# будет элементарно прикрутить контроллер для связи с ИИ-ассистентом.
### 2.3. Что потребуется реализовать на C# (.NET)

  Если бэкенд вы пишете на C# (например, ASP.NET Core Web API / Minimal APIs на .NET 8 или .NET 9), вот его ключевые
  зоны ответственности:

  1. HttpClient с байпасом SSL:
  У grade.sfedu.ru регулярные проблемы с сертификатами. В HttpClientHandler / SocketsHttpHandler обязательно
  настроить игнорирование ошибок валидации сертификата конкретно для этого хоста
  (ServerCertificateCustomValidationCallback).
  2. Парсер XML событий:
  Вместо fast-xml-parser в C# используется System.Xml.Linq (XDocument / XElement) для нормализации XML ответа от
  /events в чистый JSON DTO.
  3. Единый фасад API:
  Вместо того чтобы мобилка и веб ходили разными путями, C# бэк может стать единым шлюзом (BFF):
      • Валидация токенов.
      • Проксирование БРС.
      • Кэширование расписания (IMemoryCache / Redis), чтобы не дергать schedule.sfedu.ru при каждом запросе.
      • Swagger / OpenAPI для автоматической генерации клиентов на фронте и мобилке.

#### Tailwind vs Обычный CSS (что лучше для первокурсников?)
**Однозначно Tailwind.** И вот почему:
* В обычном CSS первокурсники начнут писать стили в одном общем файле или плодить селекторы вроде `.box1`, `.block-text`, `.my-table-2`. Через 3 недели в гите начнется ад из конфликтов слияния (merge conflicts), и стили одного человека будут ломать верстку другого.
* В Tailwind классы пишутся прямо в JSX (`className="flex p-4 bg-white rounded-xl shadow"`). Первокурсник отвечает за свою карточку, стили изолированы внутри компонента и ничего чужого случайно не сломают. К тому же шпаргалка Tailwind осваивается за 1 вечер.

#### Redux Toolkit + LocalStorage
* **Связка отличная.** В Redux Toolkit (RTK) хранятся текущее состояние авторизации, загруженные баллы и расписание на неделю.
* Забудьте про Redis. **LocalStorage / SessionStorage на клиенте — это именно то, что нужно.** 
  * Залогинился $\to$ токен сессии в `sessionStorage`.
  * Скачали расписание и оценки $\to$ положили слепок в `localStorage`.
  * Пользователь обновил страницу $\to$ данные мгновенно взялись из `localStorage` без белого экрана и ожидания, а в фоне тихо пошел запрос на обновление.

### 3. Идея с ИИ-ассистентом (Killer-фича от организатора)

Это лучшая идея, чтобы гарантированно закрыть проект на максимальный балл. Жюри сейчас обожает практическое применение LLM.

**Как это сделать без сложного машинного обучения за пару дней:**
Вам не нужно обучать свою нейросеть. Вы берете готовый API (например, бесплатный/дешевый **GigaChat API** от Сбера, **YandexGPT** или **Groq / DeepSeek API** через бэкенд).

**Схема работы («Контекстная инъекция»):**
1. Студент пишет в чат: *«Где сейчас сидит Иванов И.И.?»*
2. Ваш C#-бэкенд перехватывает этот запрос, берет текущее время (например, *вторник, 11:55*) и дергает расписание преподавателя из API ЮФУ.
3. Бэкенд склеивает скрытый системный промпт для нейросети:
   > *«Ты — справочный ассистент Мехмата ЮФУ. Текущее время: вторник, 11:55. Вот расписание преподавателя Иванова: с 10:00 до 11:35 — пара в ауд. 215, с 11:50 до 13:25 — пара в ауд. 312. Ответь кратко студенту на его вопрос: "Где сейчас преподаватель?"»*
4. Нейросеть отвечает готовым человеческим текстом: *«Сейчас у Иванова И.И. начинается пара в 312 аудитории (до 13:25). Если не успеете, следующая пара у него на 4 этаже»*.
5. То же самое с баллами: студент спрашивает: *«Сколько мне осталось до автомата по терверу?»* $\to$ в промпт подмешиваются его текущие баллы (например, 42) $\to$ бот отвечает: *«У тебя 42 балла. До порога автомата (71 балл) нужно набрать еще минимум 29 баллов на КТ-2 и контрольных»*.

### 4. План реализации по 4 этапам проекта

#### Этап 1: Представление идеи (Код не нужен)
* **Что подготовить:**
  * Презентация (5–7 слайдов): Проблема $\to$ Решение $\to$ Стек (React + C# ASP.NET + ИИ) $\to$ Архитектура сервиса $\to$ Команда.
  * Кликабельный или статический прототип в **Figma** (2–3 экрана: дашборд оценок, экран расписания, окошко чата с ассистентом).
  * Четкое распределение обязанностей (кто пишет C#, кто фронт, кто интеграцию с ИИ).

#### Этап 2: Нулевая версия (Proof of Concept / MVP)
* **Что должно работать:**
  * Базовая связка C# бэкенда и React фронтенда.
  * Работающая авторизация: ввели логин/пароль ЮФУ $\to$ бэкенд ответил токеном.
  * Отображение «сырого» списка предметов и баллов из БРС на экране.
  * Отображение сырого расписания группы на сегодня.

#### Этап 3: Предзащита (Рабочий продукт)
* **Что должно работать:**
  * Красивый интерфейс на Tailwind (карточки предметов, цветные шкалы баллов).
  * Кэширование в `localStorage` (интерфейс загружается мгновенно, не моргает).
  * Расписание с переключением дней и недель.
  * **Подключенный ИИ-ассистент:** чат-виджет в углу экрана, который умеет отвечать хотя бы на сценарий «Где преподаватель?» и базовые вопросы по оценкам.

#### Этап 4: Итоговая защита (Полировка и триумф)
* **Что показываем жюри:**
  * Живое демо без багов (Live Demo): авторизуетесь с реального аккаунта одного из членов команды.
  * Показываете сценарий: выключаете Wi-Fi в браузере $\to$ обновляете страницу $\to$ сайт все равно открывает оценки и расписание (демонстрация кэша).
  * Задаете в прямом эфире вопрос ИИ-ассистенту и получаете точный ответ.
  * Демонстрация вкладки `Network` в браузере: быстрая загрузка благодаря связке C# + React.

### 5. Распределение ролей в команде под новый стек

* **Второкурсник 1 (Teamlead / Frontend Core):**
  * Сборка скелета проекта на Vite + React (JavaScript).
  * Настройка Redux Toolkit и логики взаимодействия с `localStorage`.
  * Организация компонентов, код-ревью первокурсников.
* **Второкурсник 2 (Backend / C# ASP.NET Core):**
  * Написание API-контроллеров для авторизации и запросов к БРС и Расписанию ЮФУ.
  * Решение проблемы CORS.
  * Реализация эндпоинта для связи с API выбранной нейросети (GigaChat/YandexGPT/Open-source модели).
* **Второкурсник 3 (Frontend / Интеграция и сложные модули):**
  * Верстка и логика интерактивного расписания (переключение дней, подсветка текущей пары).
  * Написание плавающего виджета чата с ИИ и связка его с бэкендом.
* **Первокурсник 1 (Модуль контекста для ИИ):**
  * Логика подготовки данных для промпта: функции на бэкенде или фронтенде, которые по ФИО преподавателя находят его аудиторию в текущий час из JSON-файла расписания.
* **Первокурсник 2 (UI-компоненты БРС):**
  * Верстка карточек предметов на Tailwind (название, преподаватель, шкала баллов от 0 до 100, подсветка: зеленый $\ge 60$, желтый, красный).
  * Индикаторы контрольных точек (КТ-1, КТ-2).
* **Первокурсник 3 (UI-компоненты профиля и расписания, тестирование):**
  * Верстка шапки сайта (аватар/инициалы, группа, статус сессии) и блока пар на сегодня.
  * Тестирование интерфейса на мобильных экранах, оформление документации проекта.
